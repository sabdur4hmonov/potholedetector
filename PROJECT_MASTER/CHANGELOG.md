## 2026-10-12 — CAM-001 whole 4:3 sensor image and capture tuning

The Drive analysis stream used the deprecated `setTargetResolution(1280×720)`. On a 4:3 phone sensor, that 16:9 stream drops the top and bottom of the image, a full-frame violation: the preview (4:3, FIT_CENTER) showed more road than the detector received. Analysis, preview and optional video now all request 4:3 through `ResolutionSelector`. Analysis targets 1440×1080, so evidence goes from 720p to about 1440×1080. Video stays SD, at 4:3. Camera2 interop sets an auto-exposure frame-rate floor (the highest range from 20 to 30 fps the phone offers), continuous-video autofocus when available, and electronic stabilisation off, because it crops. Burst sharpness is measured at 320 px instead of 160. Browser Drive requests 4:3 1440×1080 instead of 1920×1080. `full_frame_invariant_test` now fails on any 16:9 or `setTargetResolution` regression. There is deliberately no absolute blur gate until road data exists.

## 2026-10-12 — MOD-001 names, HELP-001 guide, ONDEVICE-002 runtime, SEC-006 test refresh

* **MOD-001 ranking name moderation.** The community server refuses display names, districts and villages containing Uzbek, Russian or English insults, names posing as officials (YHXX, GAI, police, admin, prezident…) or links and phone numbers. Matching runs on a normalised form: Cyrillic transliterated, look-alike digits mapped, separators and repeated letters removed. Short words are matched only as whole words, so names like Sikandar or Assalom pass. A refusal carries the code `name_not_allowed`, which the app turns into a translated explanation. Rankings show "Haydovchi" for names the operator hides with `--hide-name` and for names a later list catches. Renaming clears the hidden flag and the new name is checked again. * **HELP-001 in-app guide.** A "?" button next to Settings opens an eight-section English/Uzbek guide: mounting, Drive, pothole warnings, Antiradar, Route and navigation, trips and rankings, missing voice (Android TTS) and safety. It is rendered with `textContent` only.
* **ONDEVICE-002 dormant LiteRT runtime.** `OnDevicePotholeModel` loads `assets/models/pothole_detector.json` and its `.tflite` only when the card passes `OnDeviceModelSpec`. It refuses any model whose tensors are not exactly one float32 `[1, h, w, 3]` frame in and one probability out. Each complete frame is stretched with `Bitmap.createScaledBitmap`. In sensor mode every burst frame is scored, `decideBurst` decides, and the shock report records whether the camera model agreed. The model never creates or suppresses a report. Without a bundled model, and no model ships, Drive is unchanged. New dependency `com.google.ai.edge.litert:litert:1.4.0`.

## 2026-10-08 — NAV-001 voice turn-by-turn navigation

The community server now returns OSRM turn steps. A pure `NavigationGuide` snaps each GPS fix onto the route line, announces the next real manoeuvre early (≈30 s, 400–1200 m), close (≈10 s, 80–300 m) and now (15–40 m), skips noise steps (depart, same-road name changes), handles roundabout exits, forks and ramps, reports leaving the route once after three accurate fixes more than 50 m off, and announces arrival within 30 m. Wording in Uzbek, Russian (voice fallback) and English. It runs in the GPS-only `RoadAlertService` together with pothole/camera warnings; a turn is spoken first and a hazard warning waits its turn. The Route screen gets Start/Stop, a large next-turn panel and automatic rerouting from the car's position. Needs the community server like routing itself.

## 2026-10-07 — SENSOR-001 AI-free sensor Drive mode

Drive can now start without an AI key. A pure `RoadBumpDetector` projects 50 Hz accelerometer samples onto a low-pass gravity estimate, flags a short vertical peak-to-peak swing above the chosen sensitivity at 14 km/h or more, ignores phone handling, warm-up and stale speed, and holds each shock 600 ms for confirmation. `SensorDriveDetector` keeps a short ring of complete primary frames and saves the one captured about 8 m before the hit as an unverified "road shock" report; `DriveDetector` lets the service run either it or the cloud engine. Web: Settings choice (automatic / sensor only) and sensitivity, English/Uzbek text, HUD shock count, a separate native import path that never marks a shock as a pothole, deduplication of repeated shocks, and labelling/export as training data. Privacy page mentions the accelerometer.
