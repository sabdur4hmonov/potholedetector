# SENSOR-DRIVE-001 — private accelerometer Drive fallback

Owner-authorized implementation, 2026-11-04. Owner chose accelerometer sensor mode as the AI-free Drive fallback until the vision model exists. This records bumps for post-drive human review; there is no vision model or accuracy claim.

## Mode, detector and evidence

- Without a stored OpenAI key the page explicitly requests `detectionMode: sensor`; both the native plugin and service independently force sensor mode for a blank key. With a key the page requests existing cloud Drive. Dashcam remains disabled and sensor mode accepts only the phone camera.
- Sensor mode never constructs the cloud inference engine or starts its worker. The adapter has no network client or AI-budget call. Existing evidence capacity reservations reserve disk bytes, not paid inference. No provider calls were used for validation.
- Android-free `NativeBumpDetector` projects linear acceleration onto the gravity unit vector and accumulates the signed absolute peak within 300 ms. Speed must be at least 4.2 m/s. The refractory period is 2,000 ms between event peaks; low/medium/high thresholds are 6.0/4.5/3.0 m/s², default medium. Constant-size peak state replaces any sample list. The raw accelerometer fallback uses an alpha 0.8 low-pass gravity split; pause resets gravity.
- The adapter prefers linear acceleration plus gravity, otherwise accelerometer, at `SENSOR_DELAY_GAME`. Registration follows actual capture admission and is released on interruption, pause, stop and destruction. Missing sensors produce visible status. Existing camera/privacy/notification/fresh-GPS interlocks remain. Speed is unknown if the latest fix is older than 5 seconds or accuracy exceeds 30 m.
- Selected bursts still use `persistSelectedBurst`. Sensor rows are inserted as already analyzed, so process death cannot turn them into pending paid replay. At most 16 persisted primary references are retained; bursts older than 8 seconds are pruned through verified deletion and media byte accounting.
- An event chooses the newest persisted primary in inclusive `[event−4000, event−150]` ms. GPS is nearest the event within 5 seconds, otherwise the burst fix. No matching primary means no invented photo and an incremented missing-frame count.
- Report JPEG/thumbnail use that complete primary, existing whole-frame encoding, the 512 MiB report-evidence quota, media mutex and Room transaction. Sampling retains the existing 4 GiB media cap. No crop, tile, mask, road band or extra model evidence is added.
- Sensor reports use `captureSource=drive_sensor`, `detectionModel=sensor-accelerometer-v1`, no prompt/size, `decision=needs_review`, `assessment=unverified`, `status=draft`, no AI pothole/reportable verdict and no measurement claim. Description/speed contain the signed peak and speed. Photo time is primary capture time; report creation/last-seen time is the event.
- Only another sensor report in the same drive within 15 m merges. The existing ownership donation handles an already acknowledged row, and native seen count increments; the cloud verdict matcher is not used. Web import scans only that drive one row at a time in a committing IndexedDB transaction. Retries preserve native identity, human confirmation and labels.
- Reports own separate JPEGs, so normal stop releases all sampling bursts. Finished/interrupted sensor history retries cleanup after process death. Sensor frames cannot become pending AI replay. Report evidence remains subject to existing durable native-to-web acknowledgement and deletion ownership.

## Review, log and privacy

English/Uzbek HUD identifies sensor mode, bumps and bumps without frame. Settings persist sensitivity and label the key optional. Cards/detail show an unconfirmed badge, complete photo, time, coordinates, peak and speed. Confirm marks a private user-reported pothole; Delete removes the web report and native sensor row. Evidence export is explicitly unconfirmed or user-reported. Dataset export does not invent `model_said` for sensor observations. Nothing is submitted officially.

Each sensor drive writes `filesDir/sensor_logs/<session>.csv`: at most 20,000 window peaks with magnitude at least 2.0 m/s², including below-threshold/unknown/slow-speed peaks. Columns: elapsed milliseconds, anchored ISO wall time, signed peak, speed, latitude, longitude, accuracy, trigger flag. Unknown values are blank. A small sidecar retains bump/missing counts.

Logs include precise peak locations until Delete All, independently of optional raw tracks and their existing 30-day purge. The sensor tip discloses this owner-requested calibration retention. Finished-drive Share sensor log grants temporary read-only access through the dedicated narrow `sensor_logs/` FileProvider alias. SEC-002's private-media registry and URI revocation include logs and sidecars. No dependency or Room schema changed.
